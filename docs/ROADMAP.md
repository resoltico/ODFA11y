# Roadmap to v1.0.0

ODFA11y helps people audit sources, make explicit decisions and verify publications.
Keep source validity, semantics, native capability, PDF machine checks, fidelity and human
acceptance separate. Prefer preservation and explicit refusal over guessing. Replace a
mechanism when evidence supports a simpler complete solution.

## v0.8.0 — foundations and text structure

The current draft implements the [application API](API.md), typed outcomes/records/facts,
published schemas, source-bound decisions, content checkpoints and explicit family contracts.
Presentation/drawing share page semantics; native/PDF responsibilities and tests follow their
owners. Generated references describe the shipped surfaces; dependencies and native CI
inputs are refreshed from primary sources.

Text audits cover lists/continuations, links/bookmarks/cross-references/notes, effective
paragraph/inline script-channel language, table classification and revision/visibility
relationships. Target-language decisions preserve unrelated overrides. Columns, floating
frames, sections and notes retain reading-order review. Schema publication, public-surface
reduction and plan/source binding are part of this milestone.

Qualification uses real positive/negative native fixtures and recorded exporter limits,
including detection controls where native output is insufficient. [Verification records](verification/0.8.0.md)
state actual results. Publication still requires owner approval and hosted qualification of
the exact release revision through [Releasing](RELEASING.md).

## v0.9.0 — data documents and human review

Planned work deepens spreadsheet/chart, form and embedded-object semantics without evaluating
formulas, executing submissions, SQL or connections, or fetching resources. Header decisions
must distinguish print repetition from actual data relationships and preserve values,
formulas, references and hidden state.

Build the human-review record on existing decisions/source binding and artifact digests.
Relevant changes must invalidate review; a checkbox alone is not acceptance. Expand the
corpus across independently authored producers and document keyboard/screen-reader results.
Publish measured capabilities by family, producer and exporter.

Completion requires reviewed end-to-end text, spreadsheet and page-document examples,
source-only examples for other families, and positive/negative review-invalidation and
preservation controls. Native limits remain explicit boundaries with actionable guidance.

## v1.0.0 — stabilize and qualify

Stabilize supported APIs, CLI, plans, findings/locations, schemas, evidence and exit meanings.
Complete standards-to-capability review: implemented checks, explicit human tasks and
unsupported boundaries must be traceable to code and evidence. Qualify supported OS/tool
combinations and representative documents, reproducible artifacts, independent review and
human acceptance. Release only when these contracts and required checks are established.

[ODF 1.4](https://docs.oasis-open.org/office/OpenDocument/v1.4/) and
[BCP 47](https://www.rfc-editor.org/rfc/rfc5646) guide semantics; specifications alone do
not establish application behavior. An ODF 1.4 feature must not silently relabel 1.3 sources.
